# 记录口径

按终端、应用和时间分区保存延迟直方图，对同一边界的独立分区做计数汇总。

直方图 bins 为 [lower, upper, count]，区间左闭右开，count 为频数。流中 occurred_ms 是事件时间，partition_id、revision、operation 描述分区事实，操作为 upsert 或 retract。预算只计算保留的分布数据及索引文件，不含程序和只读输入。

数据字段采用稳定的英文标识符。编号是业务身份，不由输入数组中的位置决定。未到达的结果与已经观察到的否定结果是不同事实。货币、时间和统计单位应按字段约定解释，不在读取时默默变换。

当前命令的输出只解释当前公开计算，不承诺示例覆盖全部业务情形。批量重放应使用新的输出位置，避免人工查看上一次运行留下的文件。

## 摘要结构与索引布局（query_service）

终端只保留有容量上限的摘要，原始调用在构建摘要后即可过期。每个活跃分区一份
`part-<id>.json`，内容是「40 个对数延迟 bin（另加下/上溢出桶）× 10 个时间子桶」
的整数频数矩阵，加上分区身份、revision、窗口和各子桶实际事件范围；分箱边缘全仓库
统一，只在 `schema.json` 存一份。状态里没有原始样本，也没有每个不同取值的清单，
重复值无论出现多少次都只增加对应频数。

`index.json` 记录每个分区的当前最高 revision、active/tombstone 状态、内容指纹、
摘要文件名与落盘字节数。字节预算按分区文件单独核算，写入超限即报错并回滚，
不把超限文件留在状态目录；schema 与索引是共享的固定开销，不计入单分区预算。

## 查询速度、内存与可撤回性的取舍

* 不维护跨分区的预聚合物化文件。查询时读取命中的活跃分区摘要，在内存里按固定
  分箱累加频数。好处是替换（更高 revision 的 upsert）和撤回（retract）只改动一个
  分区文件，旧事实不可能在聚合体里残留或复活；代价是查询成本与命中分区数成正比，
  分区规模很大时需要在分区窗口粒度上另做分层索引。
* 摘要不要求可相减。撤回后的统计等价于只拿当前有效分区重新建索引，测试用逆序
  重放最终事实的方式核对两条路径结果完全一致。
* 时间子桶是查询精度与内存的折中：桶越细，边缘查询的不确定区间越窄，但频数矩阵
  越大。当前固定 10 个时间子桶，单分区落盘约 3.6KB，服从 4096 字节预算。
* 全仓库共用同一套固定分箱，只有同构摘要允许相加；不同误差语义的摘要（例如未来
  引入的抽样摘要）必须带不同 schema 标识，不能与本确定性摘要互换。

## 误差语义约定

分位数采用最近秩 `k = ceil(quantile * N)`（1 基秩）。分箱只给出值域界限：报告的
`lower/upper` 是基于嵌套样本阶统计量不等式的严格边界，`estimate` 仅为所在 bin 的
几何均值点估计；上溢出桶没有有限上界时 `upper` 为 null。查询窗口切到时间子桶
中间时，被压住的子桶整体只进入上界，`target_rank` 与 `rank_uncertainty` 说明秩的
不确定来源（分箱内秩与窗口边缘秩分别给出）。

超阈值计数是「严格大于阈值」的整数上下界，阈值恰好落在 bin 边缘且窗口完整时
`exact` 为真，否则只给界限。分位数的值域界限与阈值计数的整数界限语义不同，
输出中分别标注，不得互相替代或当作可互换的近似数。信息不足时允许返回上下界或
`no_data`，不允许声称精确。
